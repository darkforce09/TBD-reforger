# T-946.55 — Plan

## Context
`TBD_ObjectivesComponent.c:692` calls `ReplicateHud` every `Deliver` tick with no dirty check,
sending a Reliable Owner RPC of three string arrays per connected player at 1 Hz. Cost scales with
players x objectives and never falls to zero on an idle round — which can exceed the chat pump
T-941.4 removed, making the fix a regression on its own metric.

## Approach
1. Verify: record RPCs per player per minute over an idle round with nothing changing. Paste it.
2. Keep a per-owner last-sent board (hash or snapshot); gate the RPC on a difference.
3. Force a full send on first sight of an owner so a mid-round joiner is not starved.
4. Clean the per-owner state on disconnect so it is bounded by players, not session length.
5. Perturbation: make the dirty check always report dirty → the idle-round assertion goes red;
   restore, `touch`, green.

## Risks
- **Starving a joiner** is the obvious way to break this — the dirty check must not suppress the
  first board an owner ever sees.
- **ENFUSION twins.** Both `tbd-framework` and `tbd-export` copies must change identically; the
  export tree is ASCII-only and `mirror_lockstep` holds them in step.
- No gate step compiles Enfusion — run `cargo xtask mod compile` by hand and paste the verdict.
  Never concurrently with `cargo test -p xtask` (shared `~/.local/share/tbd-server-addons`).
