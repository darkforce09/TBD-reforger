# T-946.23 — Plan

## Context

The T-674.2 slice agent could not explain why its framework-only probe compiled clean, went looking,
and found that the gate reads `tbd-export` for every shared path. The command centre reproduced it
before touching anything: a planted undefined function in the framework copy gives exit 0.

## Approach

1. `xtask/src/gate_mod_compile.rs`: flip the addon string to `TBD_Export,TBD_Framework` so the
   shipping copies are the ones compiled, with the measurement recorded in the comment.
2. Add `mirror_lockstep`, run before the ASCII scan: for every `Scripts/Game/**/*.c` in `tbd-export`
   that has a `tbd-framework` twin, strip comments and string literals from both, normalise
   whitespace, compare, and fail with the paths that differ.
3. Reuse `schema_gates::strip_enfusion_comments_and_strings` rather than writing a second stripper;
   it is the same "count code, not prose" rule the unread-field gate already depends on.

## Risks

Flipping the order could in principle change which copy of a shared *asset* the engine resolves, not
just scripts. It does not: the overlay is per path and both trees carry the same paths, so the only
difference is which identical-by-design file is read. The lockstep check is what makes that claim
enforceable instead of assumed.

If the two trees ever legitimately need to differ in code, this gate blocks it — deliberately. The
convention is that they are mirrors.

## Verification

- Plant an undefined function in a framework shared script: the gate must FAIL naming that file.
- Clean tree: `OK: compiled clean`.
- `cargo test -p xtask`, `clippy -D warnings`, `rustfmt --check`.
