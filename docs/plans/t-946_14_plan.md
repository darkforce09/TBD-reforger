# T-946.14 — Plan

## Context

Landing T-675.1 into wave 241 aborted after the merge: the post-merge gate was handed pre-merge HEAD
as its base and the T-602 base check refused it. Two more slices are still to land this wave, so
every one of them would abort the same way.

## Approach

In `xtask/src/wave/land.rs`, keep the pre-merge HEAD as the revert target and pass an empty base to
`gate::cmd_gate` so it derives one from the close-marker ledger. Retitle the printed value from
`wave base:` to `revert target:` so the two jobs are not conflated again, and drop the stale base
argument from the "fix on main and re-run" hint.

## Risks

The gate now covers the whole span since the close marker rather than just the merge, so a land is
slower and can go red on something an earlier land introduced. That is the correct behaviour: a gate
that reports on a wave must read the wave. Rollback advice is unchanged, because the revert target
is unchanged.

## Verification

- `cargo test -p xtask`, `cargo clippy -p xtask --all-targets -- -D warnings`, `rustfmt --edition 2024 --check`.
- The next `platform wave land` reaches its bookkeeping step instead of refusing at the base check.
