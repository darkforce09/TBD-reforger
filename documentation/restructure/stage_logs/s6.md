## Findings

Findings are triaged FIX, NOTE or CLOSE; ids are `F-S6-NN`.

- **F-S6-01 (FIX, stage records): the S6 rows of the crate catalogue miss or invert eleven
  dependencies.** spatial_indexes also takes the TLAS build core and `segment_aabb_window` and
  needs a `test_fixtures` feature; prefab_catalog takes the payload decoding (`WorldError`,
  `bytes_to_json`, flate2) that sits in the world store today; world_chunks leaves
  `loaders/residency.rs` (eight `impl WorldResidency` blocks) to the chunk scheduler; world_store
  depends on prefab_catalog; road_network takes the road-class codec and does not use
  map_draw_lanes; unit_symbology depends on map_draw_lanes (`px_to_m_at_zoom`); overlay_instances
  depends on map_draw_lanes (`LaneRole`) and not on spatial_indexes; label_layout leaves the
  location packers to place_names; interior_line_of_sight depends on spatial_indexes directly;
  world_line_of_sight depends on spatial_indexes, building_interiors and prefab_catalog;
  building_interiors' section index joins the shared BVH core. The cut wave makes the code match;
  the catalogue rows change with the stage commit.
- **F-S6-02 (NOTE, coordination): S4's switch deletes re-export facades inside S6's modules**
  (`world/mesh.rs`, the `overlay/lod.rs` graphics re-export, the `text_metrics` and `text_packing`
  graphics re-exports, `bvh/tree/mod.rs`, `blueprint/model/mod.rs`, `los/world/descriptor/mod.rs`)
  and adapts the loaders to `browser_platform`; the rebase of the cut wave onto S4 resolves those
  conflicts. S5 shares the map engine's features, `lib.rs`, the feature-gate tripwire and the
  frontend and developer_tools feature lists; the second of S5 and S6 to land rebases.
- **F-S6-03 (CLOSE, coordinator: one target folder per worktree, A5): the four worktrees share one cargo target folder,
  and cargo reuses another worktree's build when this worktree's sources are older.** A workspace
  member's fingerprint holds its path relative to the workspace root and the source mtimes, not
  the worktree, so after S3 rebuilt xtask with a lowered frontend-layering ceiling (6 and 0), this
  worktree's `cargo xtask ci verify-workspace-laws` ran S3's binary and failed on a ceiling its
  own source does not hold (12 and 3); after touching the law's source it passed. Any gate in any
  worktree can run another worktree's code for a crate it did not edit last. Stage S6 touched every
  member's `lib.rs`/`main.rs` before each gate command (A2) until each worktree got its own
  target folder (A5).
