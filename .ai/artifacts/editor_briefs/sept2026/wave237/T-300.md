## THE TICKET
A binary built inside a slice worktree counts as fresh for a main-checkout build under the shared CARGO_TARGET_DIR, so run-style lanes can execute unmerged code; run-only binaries get their own target and preflight checks the build stamp.

Main goal: No run lane launched from the main checkout ever executes a binary that a slice worktree built.

Context:
  - Found by T-192's agent in wave 1: `make api` on :8080 served unmerged slice code after a worktree build; `cargo clean -p website-api` fixed it.
  - Anchor 2026-09-05: wave/mod.rs:241 Ctx::cargo_target_dir exports one shared dir for every worktree; platform_preflight.rs:398-403 only asserts the variable is set.

Current state:
  - Ctx::cargo_target_dir points every worktree and the main checkout at one target; nothing records who built a run binary.
  - platform_preflight.rs step 4 checks CARGO_TARGET_DIR is set and non-empty, nothing more.

Requirements:
  - Run-style lanes (api serve, world-boot, smoke) build into a dedicated `<CARGO_TARGET_DIR>/run-main` target so worktree fingerprints never satisfy them.
  - Preflight reads a build stamp (sha + checkout path) next to each run binary and goes red with a named fix when it disagrees with HEAD.
  - Check, test and clippy keep the shared dir; no per-worktree targets (44 GB each).

Approach (the ticket's own; deviate only with a stated reason):
  - Add Ctx::run_target_dir in wave/mod.rs; run lanes export it as CARGO_TARGET_DIR and write `tbd-built-from` (sha, path) beside the binary.
  - Preflight step 4 compares the stamp with `git rev-parse HEAD` and names the stale checkout on mismatch.
  - Perturbation: stamp a wrong sha; preflight must go red; restore, touch, green.

Done means:
  - A binary built in a worktree is never executed by a main-checkout run lane; the run target is separate.
  - Preflight names the stale binary and the checkout that built it when the stamp disagrees with HEAD.
  - Disk use grows by one extra target, not one per worktree.
