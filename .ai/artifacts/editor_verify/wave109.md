## MAJOR-1 (T-079) — the owner-line rAF's per-frame body is a full uncached SoA materialization: selecting an owned trigger costs O(n-slots) sixty times a second

**Evidence.** The self-contained rAF loop (eden_dock_right.rs:1884-1908) bumps `tick` every frame while `selected.get_untracked().is_some()` (:1895-1896). The subscribed projection closure (:1911-1935) then runs per frame: `ops::owner_line_world(sel)` FIRST (:1917) — which calls `trigger_rows()` (serializes the whole `triggersById` map to a JSON String and serde-parses it back, editor_ops.rs:4058+) and, when the row carries an `ownerId`, `placed_entity_pos` → **`core.materialize()`** (editor_ops.rs:4183-4197) — a full, uncached SoA rebuild: walks every `editor_layers.entityIds` array plus every slot YMap, building four interners and all columns (store.rs:552-620, no memoization anywhere on the path). A DANGLING owner pays the same full materialize per frame (the id is searched and not found) and then draws nothing. There is no change-detection of any kind — the loop polls whether or not the camera, doc, or selection changed (the ruler/LoS overlays are event-driven off `cursor`/`debug_hud` heartbeats instead; the deviation to a rAF is owns-boundary justified in the comment (:1866-1871), but the justification covers the LOOP, not the per-frame body).

**Impact.** Derivation of magnitude (no bench added — read-only): materialize is a yrs-map walk + column build over n slots; the repo's own measurements put a 367k-slot JSON parse at 615.6 ms and a byte-scan at 34.5 ms (wire_safety.rs header), bracketing a per-slot walk cost of ~0.1-1 µs → **~37-370 ms per frame at the program's live-validated 360k scale — seconds-per-frame while a trigger with an owner is selected**. Even at 10k slots it is ~1-10 ms/frame (6-60 % of the 60 fps budget) spent recomputing a value that only changes on doc edits or selection changes. Wave-108 NOTE-4 flagged k+1 materializations as tolerable for a RARE gesture; 60/s while a panel row is selected is not rare. The idle costs are fine: deselected-but-open = one no-op closure/frame; all four stop paths verified (§A below).

**Disposition.** Document only. Fix shape for the owning wave: split `owner_line_world` out of the per-frame path — recompute the two WORLD endpoints only on `doc_tick`/`selected` change (a memo keyed on those two signals), and let the per-frame tick drive ONLY the two `cam.project` calls (cheap); or replace the poll with a `camera_snapshot` equality check before bumping `tick`. Either is a ~10-line change confined to `TriggerOwnerLine`.

## MINOR-2 (T-643) — `occlusion()` mis-anchors the observer eye on a head-gapped profile: an off-coverage HEAD yields a confident false BLOCKED instead of Unknown

**Evidence.** `occlusion` anchors `eye0 = profile[0].elev_m + eye_obs` at interpolation distance **0** while `profile[0].dist_m` may be > 0 — `sample_segment`'s contract emits only the covered subset, so an off-coverage HEAD produces exactly that shape (dem/sample.rs:189-192). The sight line is then interpolated over `[0, total]` (los_tool.rs:137-142), so at the first covered sample the line has already descended/climbed. Numeric proof (scratch replica, repo untouched): head gap to d=400 at 100 m elev, target at d=800 at 0 m → the line at d=400 computes 51.8 m vs terrain 100 m → **BLOCKED at the profile's own first sample** — contradicting both the function's doc ("the profile's own endpoints … can never self-block", :124-127) and the module's honest-Unknown policy ("no usable profile … never a fake verdict"). Off-coverage TAILS are consistent (total = last covered dist, so eye1 anchors correctly); only heads break.

**Impact.** Unreachable in T-643's live editor today: the Everon manifest box covers the full island, clicks are on-map, and the 8 m grid answers everywhere inside it — the goldens' wholly-off-coverage → Unknown case is the one that occurs. Latent for **T-644**, which reuses `sample_segment` for viewshed rays; any future partial-coverage sampler (grid holes, other terrains, edge-clamped rays walked outward-in) turns a should-be-Unknown into a false BLOCKED at the coverage edge.

**Disposition.** Document; flag on T-644's brief. Fix shape: return `Unknown` when `profile[0].dist_m` exceeds ~one step (the head is not the observer), or interpolate over `[first.dist, last.dist]` instead of `[0, total]`.
