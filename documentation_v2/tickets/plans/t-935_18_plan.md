# T-935.18 — Plan

## Context
Step 1 of deleting chunking. Emit one binary container plus a spatial index **beside** the existing
`objects/chunks/*.bin`, and prove the object set is byte-equivalent before anything is deleted.

The shape already ships in this repo and must not be reinvented: `TbdsHeader`
(`crates/map-engine-core/src/world/binary/chunk_container.rs:491-500`) is 32 bytes — magic `TBDS`
(`:36`), `version:u16` (`:43`), `flags:u16`, `index_len:u32`, `reserved:[u8;20]`, with a
`size_of` assert at `:500`, accessors `tiles_offset() :529` / `index() :538`, and the shared
`ContainerHeader` trait at `:49-72` fixing magic-then-version validation order. The index is a Tier-2
rkyv archive in the shape of `TbdSatIndexV2` (`binary/archives.rs:425-434`), read only through
`access_checked`.

## Approach
1. Declare the new container version and index archive in `chunk_container.rs` + `archives.rs`.
2. Emit both from `build.rs`/`binary_emit.rs` alongside the chunks. Delete nothing.
3. Prove byte-equivalence of the object set against the chunked build. Requires T-935.17's answer on
   reaching the everon staging input from a worktree.
