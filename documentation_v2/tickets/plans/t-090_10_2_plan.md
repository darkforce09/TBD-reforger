# T-090.10.2 — Plan
## Context
T-090.5.4 and T-090.8.1 (vector parity) are shipped, so the raster "map" pyramid fallback can go. The ticket body names TypeScript files (`useTerrainBasemapLayer`, `basemapView.ts`, `terrainManifest.ts`) that no longer exist; the live branches are Rust: `world_assets/mod.rs:91,403` (`view == "map"`), `satellite.rs:652` `load_map_basemap` (`tiles/map/{z}/{x}/{y}.webp`), `settings_modal.rs:1574` (`["satellite","map"]`), `engine.rs:154` `basemap_mode` stats, and `manifest.json:62` `tiles.map`.

## Approach
1. Delete the `view == "map"` branches in `world_assets/mod.rs` and `load_map_basemap` in `satellite.rs`; the style toggle in `settings_modal.rs` keeps satellite plus the vector map style only.
2. Drop `tiles.map` from `packages/map-assets/everon/manifest.json`; relax `terrain-manifest.schema.json` so `tiles.map` is absent, not required; keep `basemap_mode` stats honest (`satellite` | `none`).
3. Leave the cartographic tooling (`tools/tbd-tools/src/map/carto.rs`, `mk_ci_tasks.rs` lanes) untouched — frozen, not deleted, per the ticket.

## Risks
- A golden or e2e fixture may still request `tiles/map`; the `rg` verify line catches it. Fallback: keep the schema key optional rather than removing it.
- Removing the raster branch changes first-paint when satellite is unavailable — the vector layers must already paint, which T-090.8.1 proved.
