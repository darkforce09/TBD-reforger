# T-090.11.2 — Offline pipeline: pak, prefabs, XOB nodes, bvh-batch

## Context

Only the farmhouse shell exists as a BVH, extracted by hand. Every child entity (door sets, window sets, glass panes, ~90 furniture props, scene trees) needs its own BLAS and a placed instance record, engine-free, straight from the game paks.

## Approach

New `xtask/src/map_blueprint/{pak.rs, prefab.rs, surface_kind.rs, batch.rs}` + `xob.rs` extensions: PAC1 pak reader (FORM/PAC1, HEAD/DATA/FILE chunks, zlib); `.et` grammar + inheritance resolver; XOB HEAD node/socket table + COLL subrange → node → `.gamemat`; `map xob-inspect`; SurfaceKind from game-material stem; `map bvh-batch --prefab` emitting one v2 BLAS per XOB into `packages/map-assets/everon/prefabs/blas/` and `<slug>.instances.json` (+ `packages/tbd-schema/schema/building-instances.schema.json`). Farmhouse closure committed with goldens.

## Risks

XOB node-record layout is undocumented: `xob-inspect` drives the RE; instances tag their source (`xobSocket` / `recon` / `prefabCoords`) so T-090.11.3 can validate or fall back. Trees without a foliage collider get a visual-LOD hull canopy (flagged).

## Verification

`cargo test -p xtask` (synthetic pak/.et/xob fixtures; real-file tests #[ignore]-gated on `~/.cache/enfusion-mcp-root`); `cargo xtask ci ci-local-schema`; xob-inspect acceptance on the farmhouse (9 subranges → 9 game materials, 1129 tris; 25 sockets).
