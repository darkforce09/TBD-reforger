# T-090.12.4 — World oracle: world-parity action, two cell pins

## Context

The T-090.11 oracle samples pairs around one entity with a whitelist filter; the world occluder needs the engine's verdict over whole cells, every entity included, terrain optionally included.

## Approach

`EMCP_WB_TbdBlueprint.c` gains action `world-parity` (`cx`, `cy`, `seed`, `maxEntities` = samples) → new `TBD_WorldTraceParity.c` in both addon twins: seeded stratified pairs in absolute engine coordinates (uniform eye-height, around a random entity, long 300–500 m, elevated ends), each traced twice on the Projectile layer (`ENTS`, `ENTS | WORLD`) with the hit prefab slug, written to `prefabs/debug/world_parity_<cx>_<cy>.json`; response carries `version: world-parity-1`. `cargo xtask map world-los --pairs` replays under `BlockPolicy` flags with per-kind buckets. Pins in `map_world_los_tests.rs` stay `#[ignore]` with a printed reason until the fixtures land (4b).

## Risks

A stale Workbench class answers `unknown action` (the detection; compile in the Script Editor). Engine foliage semantics unknown: both policies replayed, the matching one pinned. Workbench unavailable: scripts land, fixtures named as missing.
