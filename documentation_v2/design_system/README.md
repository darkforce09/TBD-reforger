# Design system

The visual language the website and the game [mod](/documentation_v2/glossary.md#mod) share: the
tokens for colour, type, spacing, radii and motion, the map symbology, the interaction patterns
the pages follow, and the Stitch token exports they were designed from. Developers and agents
read it before styling a page, a Mission Creator panel or a mod screen.

## Contents

```text
documentation_v2/design_system/
├── design_tokens.md         colour, typography, spacing, radii and motion on the website and in the mod
├── interaction_patterns.md  split pane, create over the list, slide-over dossier, inline toggles
├── map_symbology.md         unit, vehicle and marker symbols and the side tints on the map and in game
└── token_exports/           the Stitch token exports the designs came from, kept as exported
```

## How it works

Each document follows the [feature doc template](/documentation_v2/standards/templates/feature_doc.md)
and describes the code as built: `aegis.css` for the website, `TBD_UITheme` for the mod, and the
map engine's symbology tables for the map. Read the design tokens first; the symbology and the
interaction patterns build on its palette and its overlay motion. The token exports are
design-phase references: where the built interface differs from them, the difference is written
in the design tokens document, never into an export.

| Topic | Document | Code it describes |
|---|---|---|
| Colour, typography, spacing, radii, motion | [design tokens](/documentation_v2/design_system/design_tokens.md) | `apps/website/frontend/style/aegis.css`, `TBD_UITheme.c` |
| Units, vehicles, markers, side tints | [map symbology](/documentation_v2/design_system/map_symbology.md) | `apps/website/map-engine/src/overlay/symbology/`, the mod's `Systems/Markers/` |
| Lists, details, dialogs and sheets | [interaction patterns](/documentation_v2/design_system/interaction_patterns.md) | `apps/website/frontend/src/v2/core/ui/` |
| Design-phase token sheets | [token exports](/documentation_v2/design_system/token_exports/README.md) | none; generated by Stitch |

A page or screen's own design, its mockups and its differences from them live in that feature's
folder, in its feature doc and its `visual_references/`; this folder holds only what spans them.

## Boundaries

- Depends on: the feature doc template; the code listed above, against which every value is
  checked.
- Used by: the code READMEs listed above, which link here; the frontend, pages, navigation and
  Mission Creator documentation and the visual reference READMEs, which link the design tokens or
  the Aegis export; the frontend documentation's design section; the comment in `aegis.css` that
  names the design tokens document as its dark-only rule.
- Rules: a value is written as the code has it, with the file that sets it; a difference between
  the website and the mod, or between the build and an export, is written as a known discrepancy;
  documents here cover what spans features, and a single page's design stays with its feature.
