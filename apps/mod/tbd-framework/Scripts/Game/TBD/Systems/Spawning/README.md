# Systems/Spawning

Authoritative slot materialization, player character binding, possession transitions, one-life elimination, and platform authorization of deployments into event slots.

### Roles & Responsibilities
- `TBD_SpawnManager.c`: Central authority materializing pre-spawned slot bodies from mission definitions and binding joining players. `DeployPlayerEx` is the one door into the world; once a slot is assigned it asks `TBD_SpawnDeploymentGate` before preparing a body. `DeployOnReady(playerId, out why)` is the briefing button's door: the slot path first (PIE advances a LOBBY round to BRIEFING), then a PIE-only walk-on (vanilla rifleman on dry random ground) when no slot can deliver; never past ONE LIFE.
- `TBD_SpawnManagerDeploymentAuthorization.c`: The spawn manager's side of platform authorization, as `modded enum TBD_EDeployResult` (`AUTHORIZING` while the platform decides, `UNAUTHORIZED` when the seat cannot be authorized right now and the player keeps it), `TBD_SpawnDeploymentGate` (the check `DeployPlayerInternal` makes), and `modded class TBD_SpawnManager`: `OnDeploymentAuthorized` / `OnDeploymentRefused`, the admin respawn that waits on a decision, no walk-on in place of a decision, and the life ends the platform hears about (a seat changed or given back, a death, a disconnect, the round or the world ending).
- `TBD_DeploymentAuthorization.c`: Platform authorization of deployments into event seats (the running deployment names an event, `TBD_DeployedMission.GetEventId()`). Fails closed: until the event roster's slot table has loaded, every deployment is refused ("the event roster has not loaded on this server yet ..."). Once it has, a slot it does not list is not an event seat and deploys without asking (one WARNING per slot); a listed slot is asked for with a fresh `player_life_id` per spawn attempt. On `allowed` it remembers the life and its `occupancy_id` and lets the spawn manager continue; on `denied` it tells the player the platform's reason in private chat and has the spawn manager give the seat back (slot selection), except `SLOT_NOT_IN_LOADED_MISSION` - the platform does not run this server's mission for the event, a server fault: the player is told so and keeps the seat; a refusal that is not about the seat (no slot table, no runtime session, no game identity, a request the platform rejects) keeps the seat. A dead player waiting on an admin respawn stays dead. Every refusal goes to the admin audit trail, once per cause (or per player, seat and reason for a denial) per round; repeats stay in the console. Ends the life on death, disconnect, a seat change, the round's end and the world's end. A deployment without an event deploys without asking.
- `TBD_DeploymentRequest.c`: The records of one deployment request: `TBD_DeploymentRequest` (player, connection epoch, roster slot, `player_life_id`, retry state) and the decision wire struct.
- `TBD_DeploymentRequestQueue.c`: `POST .../sessions/{id}/deployments`, one request at a time. Repeats a request whose answer was lost with the same `player_life_id`, backs off exponentially, keeps each player's requests in order, and holds a request while an ended life of the same player or slot is still being reported.
- `TBD_DeploymentEndQueue.c`: `POST .../sessions/{id}/deployments/{occupancyId}/end`, a bounded retry queue (fixed capacity, exponential backoff, drop-oldest with an ERROR when full, rejected reports dropped with an ERROR).
- `TBD_DynamicSpawner.c`: World spawner instantiating mission vehicles, equipment crates, and mission entities.
- `TBD_SCR_MenuSpawnLogic.c`: Hooks into vanilla spawn logic to bypass default respawn screens in favor of TBD slot assignments.
- `TBD_SCR_PossessSpawnHandlerComponent.c`: Transitions client camera from the pre-slot overlook to the physical character body upon deployment.
- `TBD_SCR_RespawnSystemComponent.c`: Enforces one-life elimination rules, routing dead players directly into spectator mode.
- `TBD_SpawnController.c`: `modded SCR_PlayerController` — Ready & Continue's request/reply RPC pair (`TBD_RequestReadyDeploy` → server `DeployOnReady` → owner `TBD_RpcDo_ReadyDeployResult`).
- `TBD_SpawnClient.c`: client cache of the last deploy answer + `GetOnDeployResult()` `(bool ok, string why)` the briefing screen binds.

### Call Flow & Contracts
Authority-only simulation system. Communicates with `Session/Lobby/` to register slot claims and assigns player controllers to spawned character entities upon round start.

Deployment authorization: `DeployPlayerInternal` -> `TBD_SpawnDeploymentGate.Admits` -> `TBD_DeploymentAuthorization.Check` (refuses while `TBD_RosterLoader.IsSlotTableLoaded()` is false) -> `TBD_DeploymentRequestQueue` (addressed to `API/TBD_RuntimeSession.GetSessionId()`) -> decision -> `TBD_SpawnManager.OnDeploymentAuthorized` (the deploy continues through the retry step) or `OnDeploymentRefused` (the seat is given back on a denial, kept otherwise). A life's end -> `TBD_DeploymentEndQueue`. Wire contract: `contracts_v2/definitions/game-runtime-deployment.schema.json`.
