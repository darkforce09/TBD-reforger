# Systems/Mission/Loaders

The deployed mission (its verified artifact), its parse and validation, and the event roster.

### Roles & Responsibilities
- `TBD_DeployedMission.c`: The boot sequence of every world: read the deployment in effect (`GET /api/v1/game-runtime/deployment`, machine credential); take its artifact from the cache when the cached id and SHA-256 are the deployment's and the cached bytes still hash to them, else fetch it (`GET /api/v1/game-runtime/artifacts/{artifactId}`) and verify the SHA-256 of the received bytes before anything reads them; load it; declare it to the runtime session, which starts reporting it. `404 NO_DEPLOYMENT` runs no mission (ERROR). A deployment that cannot be read (no credential, no answer, a refusal) runs the last verified cached artifact with a WARNING, or no mission (ERROR) while the read repeats (backoff 2-60 s, or every 60 s). A fetch failure or SHA-256 mismatch loads nothing (ERROR) and repeats the sequence. There is no default mission. `GetEventId()` / `GetMissionId()` name the running deployment for the roster, deployment authorization and the results report.
- `TBD_RuntimeDeploymentStruct.c`: The deployment wire (`RuntimeDeployment`) with its checks (ids present, 64-hex SHA-256, 1..8 MiB), also the cache's identity file.
- `TBD_MissionArtifactVerification.c`: An artifact's exact bytes, fetched from the platform (staged in `received.json` and hashed as read back from it) or read from the cache, hashed across frames (`Core/Hashing/`) and accepted only when the SHA-256 equals the published one. The engine exposes no response headers, so the ETag and the compile diagnostics headers are not read.
- `TBD_MissionArtifactCache.c`: `$profile:TBD_MissionArtifactCache/document.json` (the exact bytes), `identity.json` (the deployment) and `received.json` (bytes being verified). Written only after a verification; the identity is removed first and written last. Reads return the document as text and as bytes (`FileHandle.ReadArray`).
- `TBD_MissionLoader.c`: Parses and validates the verified document (`LoadDocument`) and answers every query about it; resets per world. `MISSION_FILE_MAX_BYTES` (8 MiB) is the document ceiling, pinned to `x-tbd-missionFileMaxBytes`.
- `TBD_MissionValidator.c`: Fail-fast validator running immediately post-parse (blocks stage progression on fatal structural errors; emits diagnostics on warnings).
- `TBD_RosterLoader.c`: Reads the event roster (`GET /api/v1/game-runtime/events/{eventId}/roster`, wire version 2, machine credential). Keeps each player's reserved seat (`armaId -> slotUid`, used for seating) and every compiled slot's platform ids (`slotUid -> orbatSlotId, eventMissionId`, used to name deployment requests). Seating settles once, on the first answer or at the stage machine's roster deadline, and a failed fetch settles it round-robin. The slot table keeps loading until it has (`IsSlotTableLoaded()`, true also for a roster that lists no slot): a fetch without an answer (network, 5xx, watchdog) is repeated with backoff from 2 s to 60 s; a refusal (401, 403, 404, a wire version other than 2, an unreadable body, no machine credential) is logged as an ERROR once per distinct refusal and repeated every 60 s. Each repeat re-reads the backend config, so a corrected credential takes effect without a restart. The event is the running deployment's (`TBD_DeployedMission.GetEventId()`); a deployment without an event has no roster. A roster counts only when its `missionId` is the running mission (the platform lists the slots of the deployment it runs; an empty `missionId` means it runs no mission of the event here). Until the table loads, deployments into event seats are refused. `Reset()` starts every world afresh.

### Call Flow & Contracts
Authority-only execution during the `LOADING` stage. `TBD_FrameworkManager.OnPostInit` -> `TBD_MissionLoader.BeginLoad` -> `TBD_DeployedMission.Begin` -> deployment read -> cache or fetch -> SHA-256 verification -> `TBD_MissionLoader.LoadDocument` -> `API/TBD_LoadedArtifactReport` (the runtime session starts, reporting the artifact) -> the stage machine leaves LOADING and `TBD_RosterLoader.BeginLoad` runs for a deployment with an event. Wire contract: `contracts_v2/definitions/mission-deployment.schema.json#/definitions/RuntimeDeployment`.
